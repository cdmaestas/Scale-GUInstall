Help

A quick reference for using Scale GUInstall — a guided GUI for the IBM Storage Scale Installation Toolkit (spectrumscale).

Unofficial community tool

This is not an IBM product. All operations target real cluster infrastructure — read every command preview before executing, especially with Dry Run off.

Getting started

Scale GUInstall has two parts: this HTML page (runs entirely in your browser) and a small backend server, scale-server.py, that runs on the installer node and executes real spectrumscale commands.

The HTML page works on its own as a command generator — in Dry Run mode every button shows the command it would run without a backend at all. You only need the backend when you are ready to execute commands for real.

Start the backend

python3 scale-server.py
# or, if installed via RPM/DEB package:
scale-guinstall

It listens on http://127.0.0.1:5001 — loopback only, never exposed to the network directly.

Work through the pages in order

Prepare Software → Node Configuration → Cluster Settings → NSD Storage → Filesystem → Protocol Services → Install & Deploy → Post Configuration.

Dry Run mode

Dry Run is on by default. Every action button generates and displays the command that would run — nothing is sent to the cluster or backend. The toggle lives in two places: the top header (always visible) and the Settings page.

Turning Dry Run off requires an explicit confirmation, and the header badge turns red with a LIVE label as a persistent reminder that commands will execute for real.

Before going live

Run the relevant pre-checks (Install & Deploy → Pre-check, or the standalone Pre/Post Checks page) first. NSD creation and filesystem operations are destructive and irreversible.

Connecting remotely

The backend binds to 127.0.0.1 only, so it is never reachable from the network directly. To drive it from your own workstation, forward the port over SSH and open this app locally:

# Interactive (tunnel closes when the terminal closes)
ssh -L 5001:127.0.0.1:5001 user@installer-node

# Background (stays open after the terminal exits)
ssh -fNL 5001:127.0.0.1:5001 user@installer-node

Leave the Backend URL field as http://127.0.0.1:5001 — the tunnel forwards it transparently. The Settings page has a tunnel helper that generates this command and tests the connection for you.

Troubleshooting

"Backend not reachable"

The page can't reach http://127.0.0.1:5001. Confirm the backend is running (python3 scale-server.py or scale-guinstall), and if you're connecting remotely, confirm the SSH tunnel is up.

SSH tunnel fails: "channel N: open failed: administratively prohibited"

The installer node's sshd has TCP forwarding disabled. Enable it and reload:

echo 'AllowTcpForwarding local' | sudo tee -a /etc/ssh/sshd_config
sudo systemctl reload sshd

Or run the bundled helper script: sudo ./packaging/enable-ssh-forwarding.sh.

Commands fail with a sudo password prompt error

The backend runs all privileged commands with sudo -n (non-interactive) so it can never hang waiting for input. The user running scale-guinstall needs passwordless sudo rights (NOPASSWD in sudoers) — without it, every toolkit and mm* command fails immediately with a diagnostic instead of silently hanging.

Ansible prerequisite warning

The toolkit requires ansible-core 2.23 or earlier; 2.24+ is incompatible. The Prepare Software page checks this automatically and warns if the installed version is too new.

Node role checkboxes are disabled

Nodes marked Client Only can't hold roles that require full toolkit management (NSD, Protocol, GUI, EMS, Call Home, Archive EE). Uncheck Client Only first if you need one of those roles.
